COMPONENT 01 · 仪表盘

Feedback Sensor Registry反馈传感器注册表

把 linter / test / 结构检查等反馈传感器统一注册，接进 tools 的 post-execute 管线——前馈有 Guides，反馈有 Sensors，两翼合上才算 harnessability 达标。

SENSORS · linter / test / structure-check → tools post-execute
COMPONENT 02 · 刹车片

Evidence Gate证据门 · turn-stopping

Evidence before assertions：断言「完成 / 修好了」之前必须先交证据。门装在 turn-stopping 原生位——正是 GABench 证明的 +2.8~+7.7 的执行期控制点。

⛔
ACCEPT

配套件：LLM 优化错误消息（正面提示注入）· 结构化等人字段 · harness coverage 度量 · 调用率仪表盘

COMPONENT 03 · 方向盘（薄）

阶段机薄包装复用 goal / plan-mode / worktree

L 层只做薄包装：寄生 goal 状态即够，做重就是再造 BMAD 轮子——危险组合清单里的第一条红线。

A 注入宪法→B 意图路由→C 工具+子代理→D 收敛环验证→E lessons

高亮两态即 V 层传感器与证据门的落位处。

COMPONENT 04 · 保险丝

安全默认值skills safety defaults

技能 = 数据区（不进指令区）· judge 异源 · fail-closed。证据轮的三个数字（46.3% 重复 / 9% L3 / ≈sudo）就是这组默认值的存在理由。

FAIL-CLOSED · 未通过判定的技能文本默认拒绝进入执行
MVP 判据 · DEFINITION OF DONE

§8被低估的 wildcard 与危险组合

// FINAL SYNCH — 风暴合上时留下的四张便签

跨轮暗线

advisory 优先，blocking 要证据背书

三条互不相干的独立证据殊途同归：Claude Code ultracode · DSH repeat-tool-reminder · superagent guard。它们共同指向同一条控制哲学。

WILDCARD · 被低估

度量学可以是第二差异化

调用率仪表盘（#79）与 harness coverage（#121）是「别人没做」的度量学：装上去 ≠ 用起来，recall_event 56.3% 从未调用就是前车之鉴。

相关条目 #79 · #121
危险组合 · 一条红线

阶段机：做重即死

做重 = 造 BMAD 轮子 ✗做薄 = 寄生 goal 状态 ✓

L 层的增量只能寄生在原生 goal / plan-mode / worktree 上；任何「自建完整阶段引擎」的冲动都会把低成本优势烧光。

沉淀出的设计规则

外置控制点 > 提示词

GABench 给强模型灌 system prompt 只有 +0.3~+0.4；执行期拦截却有 +2.8~+7.7。插件的力量不该长在「更会说话的提示词」上，而该长在 tools post-execute 与 turn-stopping 这些控制点上。
